# PersonaCore API v1

The exported TypeScript contracts and Zod runtime request schema are in src/contracts.ts. This is a non-streaming, stateless API; callers send the bounded history on every request. No server conversation store is maintained.

GET /health is unauthenticated process health, returns 200 {"status":"ok"}, and never calls a model. It is not provider readiness. The process may be healthy while chat is unconfigured.

POST /v1/chat requires Content-Type: application/json and Authorization: Bearer <CHAT_BEARER_SECRET>. This is a portfolio-server-to-PersonaCore credential, never sent to the visitor browser. No permissive CORS or execution tools are installed.

Request:

```json
{
  "locale": "fi",
  "history": [
    { "role": "visitor", "content": "Moi" },
    { "role": "assistant", "content": "Moi!" }
  ],
  "message": "Voisiko tällaiseen chattiin lisätä ajanvarauksen?"
}
```

locale and message are required; history defaults to []. Only visitor and assistant roles are allowed. Every object rejects additional fields. Strings are trimmed and must be nonempty. The latest message is separate from history. Invalid roles, unknown fields, wrong locale, per-message/history count/history total violations return 400. Oversized UTF-8 JSON body returns 413. Limits are characters (JavaScript UTF-16 code units) except MAX_BODY_BYTES and MAX_OUTPUT_TOKENS. No history or approved context is silently truncated.

Illustrative response (answer generated by the real model in operation; this example is authored documentation):

```json
{
  "answer": "Ajanvarauksen voisi lisätä vastaavaan toteutukseen. Tässä portfoliossa sitä ei ole, enkä voi varata aikoja tai käyttää kalenteria.",
  "sources": [{ "id": "services.booking", "title": "Booking capability boundary" }],
  "requestId": "server-generated-uuid",
  "metadata": {
    "durationMs": 800,
    "knowledgeVersion": "2026-10-07.1",
    "instructionsVersion": "1.0.0",
    "provider": "openai",
    "simulated": false,
    "usage": { "inputTokens": 300, "outputTokens": 50, "totalTokens": 350 }
  }
}
```

sources is an array of {id,title,url?}; titles and optional HTTPS URLs are resolved on the server from published entries only. Unknown/draft IDs, unsafe links, more than 20 IDs or provider-authored answer links fail with 502. Duplicate IDs are deduplicated. Casual/general answers can use an empty sources array. Render answer as escaped plain text, never HTML, and render citations separately as safe links. A supplied source supports provenance, not a deterministic proof that every sentence is accurate.

usage is optional and records provider token counts, not price. requestId is also returned in X-Request-Id. Client request IDs are ignored. Responses use Cache-Control: no-store. Internal instructions, entire packs, provider error details and secrets are not returned.

Error shape:

```json
{"error":{"code":"service_unavailable","message":"Chat service is not configured. Contact the service operator."},"requestId":"server-generated-uuid"}
```

| HTTP | Code | Meaning |
| --- | --- | --- |
| 400 | invalid_request | Invalid JSON/contract or input/history limit |
| 401 | unauthorized | Missing/incorrect server bearer secret |
| 413 | input_too_large | Body bytes exceeded |
| 415 | unsupported_media_type | Use application/json |
| 429 | rate_limited | Per-process shared fixed-window request limit; Retry-After supplied |
| 502 | provider_error / invalid_provider_output | Provider failure/refusal/incomplete output or invalid answer/sources |
| 503 | service_unavailable | Missing bearer secret or real API key/model; no fake fallback |
| 503 | busy | Concurrent provider capacity full; Retry-After supplied |
| 504 | provider_timeout | Overall chat deadline exceeded; provider aborted |
| 500 | internal_error | Sanitized unexpected service error |

REQUEST_TIMEOUT_MS bounds provider work against time elapsed since onRequest; incoming HTTP bodies also use Fastify/Node requestTimeout. Capacity is acquired after auth and schema validation, with no queue. The slot is held until the underlying provider settles, even if abort is ignored. Client disconnect and graceful shutdown abort calls. OPENAI_MAX_RETRIES must be 0. Both SDK construction and individual requests disable retries so one reserved attempt cannot generate multiple transport attempts.

One shared in-memory fixed-window limiter covers all POST chat attempts (including unauthorized requests) because Phase 1 has one trusted upstream server. It resets on restart and is independent per replica, with boundary bursts possible. It is separate from the persistent daily attempt and visitor controls described below. Network isolation remains required.

## Phase 2 private caller requirements

Every authenticated POST /v1/chat also requires x-personacore-visitor: a 43-character base64url anonymous identity verified/generated by the portfolio server. Never forward a browser-supplied identity. Missing/invalid identity returns 400 invalid_visitor; there is no unlimited legacy path. The route-level protection applies equally to canonical and encoded routes. CHAT_ENABLED=false disables generation. Production requires persistent DATA_DIR, and OPENAI_MAX_RETRIES must be 0.

Before provider invocation, SQLite atomically commits an aggregate and visitor daily reservation. New 429 codes: daily_limit, visitor_daily_limit, visitor_rate_limited (with Retry-After for rate limits). Database failures return sanitized service_unavailable while process health remains useful. Errors/timeouts/disconnects/crashes keep consumed reservations. Only aggregate counters and hashed identities persist. See public-demo.md for calendar days, retention, single-instance deployment, operational inspection and the distinction between attempts, successes and measured tokens.
